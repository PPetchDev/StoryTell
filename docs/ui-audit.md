# UI audit — apps/web (ตามหลัก ui-ux-pro-max)

ตรวจเมื่อ 2026-11-12 ที่ commit `d154c1b` (master, รวม working tree ณ ตอนตรวจ) — **รายงานอย่างเดียว ยังไม่ได้แก้โค้ด**

## สรุป

พบ **130 ข้อ** หลังรวมข้อที่ซ้ำกันข้ามหน้าแล้ว: **Critical 0 · High 34 · Medium 56 · Low 40**

ไม่มีข้อไหนที่ทำให้ผู้ใช้ทำงานหลักไม่ได้เลย จึงไม่มี Critical: ปุ่มหลักทุกปุ่มมีชื่อ ไม่มี keyboard trap และไม่มี action ที่เข้าถึงไม่ได้ ยกเว้นข้อ H5 ซึ่งจะกลายเป็น Critical ถ้าทดสอบบน iPhone แบบ standalone แล้วพบว่า notch บังปุ่ม Close ของ Memory drawer

ปัญหาหลักแบ่งได้ 5 กลุ่มค่ะ:

1. **ข้อมูลหาย** — autosave ไม่ลองบันทึกใหม่เมื่อล้มเหลว และไม่ flush ตอนปิดแท็บ (H1); ปุ่มลบหลายจุดลบทันทีด้วยการแตะครั้งเดียว ไม่ถามก่อนและไม่มี undo (H3)
2. **ผู้ใช้คีย์บอร์ดและ screen reader เสีย flow** — focus หลุดไปที่ `<body>` หลังกดยืนยันลบ (H2) หลังกดส่งแชต (H8) และหลังเริ่มอัดเสียง (H9); คำตอบ AI และสถานะ async ไม่ถูกประกาศ (H7, H11, H12); Memory drawer ไม่ใช่ dialog (H4)
3. **ปุ่มเล็กเกินไป** — ปุ่มที่ใช้บ่อยหลายกลุ่มเล็กกว่า 44px บางจุดต่ำกว่า 24px ซึ่งเป็นขั้นต่ำของ WCAG 2.5.8 (H22–H32)
4. **Contrast** — ขอบช่องกรอกได้ 1.1–1.5:1 (H14); placeholder ได้ 3.97:1 (H15); ชิป Nudge ในธีมมืดได้ 4.18:1 (H16)
5. **กราฟและรูป** — กราฟ Bond ไม่มีข้อความทดแทนและตัวหนังสือในกราฟเหลือ 7–9.5px บนมือถือ (H17, H18); รูปในแกลเลอรีและ cover โหลดไฟล์เต็มพร้อมกันทั้งหมดโดยไม่ lazy (H33, H34)

### สิ่งที่ผ่านแล้ว (ไม่ต้องแก้)

- **สีข้อความ:** ผ่าน 4.5:1 ทุกคู่ทั้งสองธีม (`node apps/web/scripts/contrast-check.mjs` และแบบ `light` ได้ 120 คู่ ไม่มีคู่ไหนต่ำกว่าเกณฑ์) รวมข้อความที่วางทับ Backdrop ในกรณีแย่สุด
- **viewport และตัวอักษร:** viewport ไม่ปิด zoom; body 16px, line-height 1.5; ไม่มี `100vh`
- **Sheet และ ConfirmDialog:** มี focus trap, Escape และคืน focus ให้ปุ่มที่เปิด
- **Bottom nav:** มี icon + label, `aria-current` และเว้น safe-area
- **ฟอร์มใน editor:** ทุก input มี `<label for>` และ error ผูก `aria-describedby` + `role="alert"`
- **tab ของ editor:** ใช้ pattern ถูกต้อง (`tablist`, roving tabindex, Home/End)
- **คีย์ Enter ในแชต:** มี guard สำหรับ IME (`isComposing`/229)
- **คีย์บอร์ดแทนการลาก:** cropper และ cover picker ใช้คีย์บอร์ดได้
- **reduced-motion:** เคารพในส่วนใหญ่
- **ข้อความยาว:** ไม่ล้นแนวนอน (`overflow-wrap: anywhere`)

## ขอบเขตและวิธีตรวจ

- **ข้อเท็จจริงของโปรเจกต์:** **ไม่มี Tailwind** และ**ไม่มี route group แบบ `(group)`** — สไตล์ทั้งหมดเป็น CSS Modules + [`apps/web/app/globals.css`](../apps/web/app/globals.css) ซึ่งมี token แค่สี (CSS variables สำหรับ dark/light) ส่วนที่ผู้ใช้ขอให้ตรวจ "tailwind config / theme" จึงตรวจที่ไฟล์นี้แทน และแบ่งกลุ่มตาม URL
- **ลำดับ:** (1) ตรวจของที่ใช้ร่วมกันก่อน ได้แก่ `globals.css`, `app/layout.tsx`, Sheet/ConfirmDialog, BottomNav, Fold, Portrait, banner และ theme/text-size (2) แยก 4 session ตรวจพร้อมกัน: Home/Gallery/Personas/Settings/Usage · Story editor · หน้าแชตหลัก · รายการแชต/Dashboard/Memory (3) รวมผล ตัดข้อซ้ำ แล้วสุ่มเปิดไฟล์จริงเช็กเลขบรรทัด
- **เกณฑ์ความร้ายแรง:**
  - **Critical** — งานหลักทำไม่ได้ หรือข้อมูลหาย
  - **High** — ไม่ผ่าน WCAG AA หรือผิดกฎในหมวด CRITICAL/HIGH ของ ui-ux-pro-max (contrast, ปุ่มที่ใช้บ่อยเล็กกว่า 44px, focus มองไม่เห็น, layout มือถือพัง, ประสิทธิภาพ)
  - **Medium** — หมวด MEDIUM (ฟอร์ม, feedback, typography, animation, ความสม่ำเสมอ)
  - **Low** — งานเก็บรายละเอียด
- **การยืนยันผล:**
  - contrast และขนาดปุ่มคำนวณด้วย node จากค่าใน CSS
  - สี placeholder วัดจริงใน Chromium (Playwright) ได้ `rgb(117,117,117)` ทั้งสองธีม
  - **ยังไม่ได้ทดสอบบนมือถือจริง:** safe-area และคีย์บอร์ดบน iOS/Android (H5, M6), ตำแหน่งเมนู ⋯ (M23), marker ของ `<summary>` (H21) และประสิทธิภาพตอนสตรีม (M32) — แต่ละแถวระบุไว้แล้ว

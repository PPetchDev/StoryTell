# UI/UX audit รอบ 3 — ของที่เพิ่มเมื่อ 2026-11-15/16 (ตรวจจากหน้าจอจริงที่ 360px)

ตรวจเมื่อ 2026-11-16 ที่ commit `ac215b8` บนชุด e2e (ข้อมูลจำลอง: Story 4 Characters, Scene, Sudden event, Endings 3 ตอนจบ, Lore set ที่ใช้ 2 Stories, Persona มีรูป, Diary 2 entries) — รายงานนี้เขียนก่อนแก้ **ทั้ง 16 ข้อแก้แล้วในวันเดียวกัน** ดูหัวข้อ "แก้แล้ว" ข้างล่าง ส่วนที่เหลือของเอกสารคือสภาพก่อนแก้

ขอบเขต: ของที่เพิ่มรอบใหญ่ล่าสุด คือ Character Diary, Endings + Epilogue + "End the story", ตอนจบที่ AI เสนอ, รูป Persona, Shared Lore (Lore set), แถวเครื่องมือของช่องพิมพ์ และชื่อแท็บหน้าแก้ Story รอบก่อนหน้าอยู่ที่ [ui-audit-2026-11-13.md](ui-audit-2026-11-13.md)

วิธีตรวจ: ถ่ายหน้าจอ 22 หน้าที่ **360×800** (ขนาดมือถือของผู้ใช้จริง ไม่ใช่ 390 ที่ชุดเทสต์ใช้) ทั้งธีมมืดและสว่าง แล้ววัดอัตโนมัติทุกหน้า: axe-core, ปุ่มเล็กกว่า 44px (นับพื้นที่กดจริง), ตัวอักษรเล็กกว่า 12px, ข้อความที่ถูกตัด, ล้นจอแนวนอน, และความสูงของรายการแชตที่เหลือ เพิ่มอีกสองสภาพ คือ ตัวอักษรขนาดใหญ่สุด และมือถือแนวนอน (800×360)

## แก้แล้ว (2026-11-16)

วัดซ้ำที่ 360×800 ด้วยข้อมูลจำลองชุดเดียวกัน (Scene 2 บรรทัด, Sudden event กำลังเดิน, ถึง Ending แล้ว):

| สภาพ | รายการแชตก่อนแก้ | หลังแก้ |
|---|---|---|
| Scene + Sudden event + Ending | 268px | **382px** |
| เพิ่ม Cue กับ Roll | 165px | **334px** |
| คีย์บอร์ดขึ้น (จอสูง 510px) มี Cue กับ Roll | ราว 0px ช่องพิมพ์ล้นจอ | **160px** ไม่ล้น |
| มือถือเล็ก คีย์บอร์ดขึ้น (จอสูง 420px) | ล้นจอ | **154px** ไม่ล้น |
| แนวนอน 800×360 มี Cue กับ Roll | 0px หน้าสูง 381px ในจอ 360px | **94px** ไม่ล้น (142px ถ้าไม่มี Cue/Roll) |
| ตอนจบที่ AI เสนอ (แถบอย่างเดียว) | ราว 180px | **91px** |

axe-core หลังแก้: 0 violations ทั้งหน้าแชต (ปกติ, มี Cue+Roll, ตอนจบที่ AI เสนอ, เมนู), Diary, แท็บ Lore (รวมตอนขึ้น Undo) และ **Home** ซึ่งเป็นหน้าเดียวที่เคยไม่ผ่าน

## สรุป

**High 1 · Medium 6 · Low 9** — ไม่มี Critical

เครื่องมือวัดแทบไม่เจออะไร ของใหม่ทำตามมาตรฐานเดิมของแอปได้ดี ปัญหาที่เหลือเป็นเรื่องเดียวกันเกือบทั้งหมด คือ **หน้าแชตมีของกองอยู่เหนือและใต้รายการแชตมากเกินไป**:

1. **แถบด้านบนซ้อนกันจนแชตเหลือนิดเดียว** — Scene strip + Sudden event + Ending กินรวม 314px รายการแชตเหลือ 268px จาก 800 และเมื่อคีย์บอร์ดขึ้นจะไม่เหลือเลย (H1)
2. **แถบของช่องพิมพ์ซ้อนกัน** — ตั้ง Cue กับ Roll พร้อมกัน ช่องพิมพ์สูง 268px (M2)
3. **แท็บ Lore มีปุ่มหน้าตาเหมือนกันหลายปุ่ม และมีคำที่อ่านผิดได้** — "Share this Story's Lore" (M3, M4)

## High (1)

**H1. แถบเหนือรายการแชตซ้อนกัน จนแชตเหลือพื้นที่น้อยมาก และไม่เหลือเลยเมื่อคีย์บอร์ดขึ้น**
- วัดที่ 360×800 ใน Chat ที่มี Scene, Sudden event กำลังเดิน และถึง Ending แล้ว:

  | ส่วน | สูง |
  |---|---|
  | แถบบน + Scene strip (2 บรรทัด) | 109px |
  | Sudden event | 98px |
  | Ending reached | 160px |
  | ช่องพิมพ์ (มีแถว Character) | 165px |
  | **รายการแชตที่เหลือ** | **268px (34% ของจอ)** |

- ตั้ง Cue กับ Roll เพิ่ม: ช่องพิมพ์โตเป็น 268px รายการแชตเหลือ **165px (21%)** เห็นข้อความได้ข้อเดียว
- แอปตั้ง `interactiveWidget: 'resizes-content'` ([layout.tsx:32](../apps/web/app/layout.tsx)) คีย์บอร์ดจึงบีบความสูงของหน้าจริง ส่วนที่ไม่ใช่รายการแชตรวมกัน 532px ขณะที่จอ 800px เมื่อคีย์บอร์ดขึ้นจะเหลือราว 480–520px **รายการแชตจึงเหลือ 0 และช่องพิมพ์ล้นขอบล่าง** (ตัวเลขนี้คำนวณจากความสูงที่วัดได้ ไม่ได้วัดตอนคีย์บอร์ดขึ้นจริง)
- หลักฐานที่วัดตรง: มือถือแนวนอน 800×360 รายการแชตสูง **0px** และหน้าสูง 381px ในจอ 360px ช่องพิมพ์โดนตัดขอบล่าง 21px
- ตอนจบที่ AI เสนอก็เข้าข่าย: แถบสูง ~180px เพราะมีสองปุ่มและคำอธิบายสองบรรทัด
- ต้นเหตุ: แต่ละแถบออกแบบแยกกันและถูกทุกอันเมื่อดูเดี่ยวๆ แต่ไม่มีกติกาว่าพื้นที่รวมห้ามเกินเท่าไร Ending เป็นอันที่ใหญ่สุดและอยู่ถาวรจนกว่าจะเขียน Epilogue
- แก้ (เรียงจากคุ้มสุด):
  1. ย่อแถบ Ending เป็นบรรทัดเดียวแบบ Scene strip: "🏁 Ending reached: ชื่อ" กับปุ่ม "Write the epilogue" ส่วนเหตุผลและคำอธิบายซ่อนไว้หลังการแตะ (160 → ~48px)
  2. ซ่อนแถบ Sudden event และ Ending ขณะช่องพิมพ์ได้โฟกัส หรือเมื่อความสูงจอต่ำกว่า ~560px แล้วแสดงเป็นชิปเล็กแทน
  3. กันขั้นต่ำให้รายการแชต (เช่น `min-height: 7.5rem`) แล้วให้แถบด้านบนเลื่อนพ้นจอได้
- ไฟล์: [ending-banner.tsx](../apps/web/components/chat/ending-banner.tsx), [sudden-event-banner.tsx](../apps/web/components/chat/sudden-event-banner.tsx), [chat-screen.tsx](../apps/web/components/chat/chat-screen.tsx)
- กฎที่เกี่ยว: `content-priority`, `scroll-fixed-coexistence`, `orientation-support`

## Medium (6)

**M1. กด "Not yet" แล้วย้อนกลับไม่ได้ นอกจาก Reset ทั้ง Chat**
- แถบบอกว่า "Not yet stops these suggestions in this Chat" แต่ไม่มีที่ไหนให้เปิดกลับ ถ้ากดพลาดหรือเปลี่ยนใจ ทางเดียวคือ Reset ซึ่งล้างทั้ง Chat
- แก้: เพิ่มสวิตช์ในเมนู ⋯ ของ Chat ใต้ "Read replies aloud" เช่น "Suggest an ending" (ค่าใน `chat.ending_suggestions` มีอยู่แล้ว ขาดแค่ทางตั้งค่า)
- ไฟล์: [chat-top-bar.tsx](../apps/web/components/chat/chat-top-bar.tsx), API ต้องรับ field นี้ใน `PATCH /chats/:id`
- กฎที่เกี่ยว: `undo-support`, `error-recovery`

**M2. แถบ Cue และ Roll ของช่องพิมพ์เป็นคนละแถว รวมกันสูง 104px**
- Cue 44px, Roll 52px เพราะข้อความ "The dice decide your next message: 11 or more succeeds." ตัดขึ้นสองบรรทัดที่ 360px
- แก้: ย่อ Roll เป็นบรรทัดเดียว ("Roll: needs 11 or more") และวาง Cue กับ Roll ในแถวเดียวกันเป็นชิปสองอันเมื่อมีทั้งคู่
- ไฟล์: [chat-composer.tsx](../apps/web/components/chat/chat-composer.tsx)

**M3. "Share this Story's Lore" อ่านได้ว่าแชร์ให้คนอื่น**
- ปุ่มนี้ย้าย Lore ของ Story เข้า Lore set ใหม่ ไม่ได้แชร์ให้ใคร และยังเป็นปุ่มที่เล็กที่สุดในส่วนนั้น ทั้งที่เป็นทางเดียวที่จะเริ่มใช้ Shared Lore กับ Story เดิมโดยไม่ต้องพิมพ์ใหม่
- แก้: เปลี่ยนคำเป็น "Move this Story's Lore into a set" และยกขึ้นไปอยู่ใต้ Lore ของ Story เอง ซึ่งเป็นของที่มันจะย้าย
- ไฟล์: [shared-lore.tsx](../apps/web/components/story-editor/shared-lore.tsx)
- กฎที่เกี่ยว: `error-clarity` (ป้ายต้องบอกว่าปุ่มทำอะไร)

**M4. ท้ายแท็บ Lore มีปุ่มกรอบประเต็มความกว้าง 3 ปุ่มที่หน้าตาเหมือนกันแต่ทำคนละอย่าง**
- "+ Add entry to <ชื่อชุด>" เพิ่ม entry, "+ New Lore set" สร้างชุด, "Link a Lore set" เปิดรายการให้เลือก ทั้งสามใช้กรอบประแบบเดียวกัน ชื่อชุดยาวทำให้ปุ่มแรกขึ้นสองบรรทัด ("+ Add entry to The Summer Road and its peoples")
- แก้: ปุ่มในชุดใช้แค่ "+ Add entry" (ชื่อชุดอยู่ในช่องด้านบนอยู่แล้ว) และวาง "New Lore set" กับ "Link a Lore set" คู่กันในแถวเดียว
- ไฟล์: [shared-lore.tsx](../apps/web/components/story-editor/shared-lore.tsx)
- กฎที่เกี่ยว: `primary-action`, `consistency`

**M5. "Unlink" กับ "Delete set" เป็นปุ่มเล็กติดกัน ห่างกัน 8px และ Unlink ทำทันที**
- Unlink ไม่ถามและไม่มี undo (ลิงก์กลับได้จากรายการ) ส่วน Delete set ลบทั้งชุดจากทุก Story กดพลาดไปโดนอีกปุ่มได้ง่าย Delete มีถามยืนยัน จึงไม่ถึงขั้นเสียข้อมูล แต่ Unlink ที่กดพลาดจะหายไปเงียบๆ
- แก้: แยก Delete set ไปชิดขวาหรือใส่ในเมนูย่อย และให้ Unlink ขึ้นข้อความพร้อมปุ่ม Undo
- ไฟล์: [shared-lore.tsx](../apps/web/components/story-editor/shared-lore.tsx)

## ที่ไม่ได้ตรวจ

- **เครื่องจริง:** ทั้งหมดตรวจด้วย Chromium จำลองที่ 360×800 ซึ่งพลาดอาการบนเครื่องจริงมาแล้วสองครั้งในรอบนี้ (Cue ตกบรรทัด, เลื่อนแชตไม่ได้) H1 ตอนคีย์บอร์ดขึ้นควรดูบนมือถือจริง
- **screen reader:** ตรวจด้วย axe เท่านั้น ไม่ได้ฟังกับ TalkBack หรือ VoiceOver
- **reduced motion:** ไม่ได้ตรวจ
- **จอกว้าง (≥1024px):** ของใหม่ไม่ได้ถ่ายที่จอกว้าง ยกเว้นแท็บหน้าแก้ Story
- **ข้อมูลจริง:** ใช้ข้อมูลจำลอง ไม่ใช่ Chat 520 Messages บน live
- **ความเร็ว:** ไม่ได้วัด

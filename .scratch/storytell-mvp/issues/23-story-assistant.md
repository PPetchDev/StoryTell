# Story assistant with Undo

Type: task
Status: ready-for-agent
Blocked by: 22
Part of: [Spec: Storytell AI MVP](../spec.md)

## What to build

- An assistant chat beside the Story form. Each instruction ("give Mira a sister", "add Scenes") is one stateless call with the current Story plus the instruction. The call returns a structured set of field changes, which may add Characters or Scenes.
- The backend applies the changes straight to the Story. The client highlights the changed fields and offers Undo for each change.
- Undo lives only in the client while the page is open. Nothing about it is persisted. Undo restores field values; it can't bring back a removed Character.
- The assistant keeps no history. Each opening starts fresh.
- It is available on every Story, including ones with Chats. A change that would remove a Character or Scene goes through the same warning as a manual removal before it applies (see ticket 29 for the effects on Chats).

## Acceptance criteria

- [ ] API tests: applying an assistant change set updates only the named fields; adding a Character respects the 6-Character limit; a removal requires the confirmation flag.
- [ ] Playwright: give an instruction, see the changed fields highlighted, press Undo, and the fields return to their previous values.
- [ ] Reopening the assistant shows no previous conversation.

## User stories covered

6–10.

- **Instruction → change set → applied.** `POST /api/stories/:id/assistant` with `{ instruction, confirmRemovals? }` (blank → `422.005.009`) makes one `story_assistant` call in JSON mode (`maxTokens` 8000, `servedFor.storyId`): the system prompt is ticket 22's `FRAME` (now exported from `story-drafting/prompts.ts`) plus the change-set shape and rules; the user message is `renderStory()` of the whole Story plus the instruction, and nothing else, so each call is stateless. The answer is `{ reply, changes: [...] }` where each change is `set` (story incl. Style fields, role, character incl. `exampleLines`, scene, startingBond), `add` (character, scene, startingBond) or `remove` (character, scene, startingBond); the model names Characters and Scenes (case-insensitive, or "Character 2" for an unnamed one) and Bonds by `from`/`toward`. The manager is `apps/api/src/manager/story-assistant/` (`story-assistant.service.ts`, `change-set-schema.ts`, `prompts.ts`), the API `apps/api/src/api/story-assistant/`.
- **Validation before anything is written** (`change-set-schema.ts`, in the manner of `draft-schema.ts`, whose Character and Scene validators it now reuses as `validateDraftCharacter`/`validateDraftScene`): every named Character, Scene and Bond must exist, every field must belong to its part, Style values in their sets, a new Character or Scene has its required fields, no self-bond and at most one Bond per direction (counting removals and additions in the same set), and the cast after the set at most 6 (`422.003.005`, the same code as a manual 7th). The validated set holds ids, in the model's order. Unreadable output is `502.005.005`, an unusable set `502.005.006` (from the client `422.005.007`); nothing is saved and the raw model text goes to the API log (warn). Domain 005 rows added to `docs/error-codes.md`.
- **Applying** goes through `StoryManagerService` only: removals first (they make room in the cast), then sets, then added Characters, Scenes and last Bonds (so a Bond may point at a Character added in the same set, referenced by name until then). The answer is `{ story, reply, changes, pending }`: `changes` lists each applied change with a label ("Mira: Voice", "Character Lena", "Scene Arrival") and, for a set, the `before` and `after` values.
- **Removals ask first.** A set that removes a Character or Scene is answered unapplied as `pending: { changes, removals }` (`changes: []`, Story unchanged) unless the request carried `confirmRemovals: true`. The client asks, then sends the same `changes` to `POST /api/stories/:id/assistant/apply` with `confirmRemovals: true`, which re-validates against the Story as it is now and applies without a second model call; without the flag it answers `409.005.008`. Removing a starting Bond needs no confirmation, as in the editor.
- **Frontend.** An "Assistant" button in the editor's breadcrumbs opens the panel (`apps/web/components/story-assistant/story-assistant-panel.tsx` + `use-story-assistant.ts`, API client `apps/web/lib/story-assistant.ts`). Above 88rem it sits fixed to the right of the form; below, at the top of the editor. Each instruction goes through the autosave chain (`commit` is now generic over its answer), so pending field edits land first; the answer replaces the Story, every changed field gets a `field-changed` outline and a "changed by the assistant" mark (added Characters and Scenes: all their fields), and the answer lists the changes with **Undo** each: a set puts the `before` value back through the normal field route; an added Character or Scene is removed again after the same in-place confirmation as the card's Remove button; an added Bond is removed; a removal says "Can't be undone". A pending set shows "This would remove … Apply these changes?" with Apply/Cancel. A failed call shows the message with Retry on the same instruction. Close drops the conversation and the Undos; reopening starts empty. Highlight keys are the rewrite keys, so `TextField`/`SelectField` got a `highlighted` prop and the cards a `highlights` set (3 lines in `character-card.tsx`, 3 in `scene-card.tsx`). CSS appended at the end of `globals.css` under its own comment. README has a "Story assistant" section.

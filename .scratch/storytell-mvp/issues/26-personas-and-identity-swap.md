# Personas and swapping identity mid-Chat

Type: task
Status: resolved
Blocked by: 24
Part of: [Spec: Storytell AI MVP](../spec.md)

## What to build

- **App-level Personas** (Name and Description only): create, read, update, delete.
- **Swap identity.** In a Chat, the user can swap the worn identity between the Story's Role and any Persona at any time. The swap is Chat state and is never rolled back by an edit; reset keeps it.
- **Effect of a swap.** The prompt's identity block, the stop strings and the guard all use the worn identity's name and description. Bonds toward the user carry over, so they stay keyed to the user, not the Persona.
- **Stamped names.** Each User Message stores the worn identity as a reference and a stamped name. Old Messages keep their stamped name after a Persona is renamed or deleted.
- **Deleting a worn Persona** falls its Chats back to the Role.

## Acceptance criteria

- [ ] API tests:
  - after a swap, the prompt carries the Persona and not the Role
  - the guard cuts lines written as the Persona's name
  - an edit doesn't undo a swap, and reset keeps it
  - renaming or deleting a Persona leaves old stamped names intact
  - deleting a worn Persona falls the Chat back to the Role
- [ ] Playwright: swap to a Persona mid-Chat and see the next User Message under the Persona's name.

**Not verified / notes:**
- **An edited User Message is restamped** with the identity worn at the edit, not kept under the name it was first sent under: the turn after it is written to the worn identity, and showing the old name over a reply written to the new one would misstate who spoke. Renames and deletes never restamp. If the user wants edits to keep the original name instead, the change is one argument in `editMessage` (pass the Message's own stamp and wear that for the turn, which then needs the turn to take an explicit identity rather than the Chat's).
- The swap is not offered as a Persona *create* from the Chat screen: Personas are made on their page. The Chat screen reads the Persona list once when it opens.
- No Persona-specific prompt cue about the swap itself ("the same person with changed details", ticket 14): the identity layer simply carries the worn name and description, and the history keeps the user's earlier lines without names. Characters may address the user by the old name for a turn; Memory and Bonds already carry over.
- Personas have no uniqueness rule (two "Rin"s are allowed; the select tells them apart only by order).
- **For ticket 31 (Snapshots):** "first-person from the user's point of view, never drawing the user beyond glimpses" should take the user from `wornIdentity(story, chat)` (`manager/chat/identity.ts`; the Chat from `ChatModelService.findWithMessages`, which loads the Persona): its `name` is who the camera is, and its `description` is the only user detail there is (spec: no appearance field for the user anywhere), useful only for glimpses (hands, sleeves). Memory for the image prompt renders `{user}` with that same `name` through `renderUser`. Snapshots should not stamp the identity: nothing in the spec asks for it.

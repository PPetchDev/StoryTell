Status: resolved
Blocked by: 07, 08, 09, 13

## Question

What is the persistent shape of Story, Setting, Scene, Character, Role, Persona, Chat, Message, Memory, Bond, Arc and Snapshot, including what a Chat reset clears and what editing a message changes?

Constraint: editing a message rewinds the Chat — see [What editing an earlier message does](15-editing-an-earlier-message.md); state from discarded messages must roll back.

Constraint: Persona can replace the Role mid-Chat with Bond and Memory carried over — see [When a Persona replaces a Role](14-persona-replacing-a-role.md).

Constraint: Bond and Arc shape — see [How Bond and Arc change](13-how-bond-and-arc-change.md). Bond is directional per pair (Character → user, Character → Character), created only where authored or where feelings form, holding a short label and a 1–2 sentence description. Arc is a per-Character, per-Chat list of steps. Every Bond/Arc change records its causing message and event (for rollback on edit and for the dashboard). Story-level optional starting Bonds and Arc directions; Chat reset restores the starting values.

Constraint: Story fields — see [Writing a Story with AI](09-writing-a-story-with-ai.md). Story: Title, Setting (one text block), Opening, Style (POV, tense, reply length). Role: required, Name + Description. Character (1–6 per Story): Name, Appearance, Personality, Voice + optional example lines, Background, optional starting Secrets, starting Bonds and Arc directions. Scene: ordered, name + situation/goal + plain-language move-on condition (optional on the last). Each Chat tracks its current Scene, and each Scene advance records its causing message and event (rolled back on edit, reset to the first Scene). Story edits reach existing Chats live, except Opening and starting Bonds/Arc directions, which apply only to new or reset Chats. Adding a Character joins existing Chats as a stranger. Removing one deletes its Bonds/Arcs in every Chat. Knowledge a Character gains in play is Memory tagged with which Characters know it, not a change to the Character. No draft/published state on Story.

Constraint: turn shape — see [How one AI turn behaves](07-one-ai-turn-prototype.md). One AI Message per turn, written by a single call and stored as ordered parts: narration, or one Character's speech tagged with that Character. Record which model wrote each AI Message (for the Drift warning). The background judge's output attaches to the turn that caused it: Bond changes, Arc steps and any Scene advance, each with its cause.

Constraint: Memory shape — see [Memory design](08-memory-design.md). Memory is a per-Chat list of short facts. Each one stores its text (the user written as `{user}` and rendered as the current Role or Persona name), its Known-by Characters, whether the AI or the user wrote it, a locked flag (set once the user writes or edits it), and an archived flag. A separate background extraction call after each turn returns adds, updates (including Known-by additions), deletes, merges and archivings, each tied to its causing message. Editing a message reverts every change from discarded messages, including Memories the AI created there that the user has since edited. Memories the user wrote from scratch are not tied to a message and survive. Chat reset empties Memory, and there are no starting Memories on the Story.

Constraint: Snapshot shape — see [Choose the image model and how a Snapshot behaves](06-choose-image-model-and-snapshot-behaviour.md). Story gains a fourth Style field, Image style (plain text). Each Character may hold one hidden reference image (Story-level, shared by all Chats, never shown as an avatar), regenerated by choice when Appearance or Image style changes. A Snapshot belongs to the Story's Gallery and stores the image (2:3, fixed size), the image prompt used, the user's optional hint, the image model, its cost, the Characters drawn (at most 3), and links to the Chat and AI Message it was taken at; one Message can have several Snapshots. Editing a message or resetting the Chat detaches Snapshots of discarded or edited Messages from the timeline (Message link cleared) but keeps them in the Gallery; deleting a Chat keeps its Snapshots with the Chat link cleared; deleting a Snapshot removes it everywhere; deleting the Story deletes its Gallery and reference images. Snapshots never roll back Memory, Bond, Arc or Scene and are never sent to the text model. Image spend is tracked apart from text spend (its own prepaid credit).

Constraint: hosting — see [Hosting and access for one user on many devices](10-hosting-and-access.md). One PostgreSQL database on the user's home Windows PC, with a separate dev database. Images (Snapshots and Character reference images) are files on the PC's disk; the database stores their path, not the bytes. There are no user, account, login or session tables, because a private Tailscale network locks access, not the app. Backups are a daily `pg_dump` plus the image folder, so every stored image path must be relative to that folder.

## Answer

Grilled 2026-11-03. The full logical model is in [the data model sketch](../assets/11-data-model.md): a mermaid ER diagram, the fields of every entity and a lifecycle table. The decisions below are what that sketch adds to the constraints above.

**Messages and turns**
- A Message is either a User Message or an AI Message.
  - A User Message stores its text and the Role or Persona worn when it was sent, as a reference and a stamped name, so old messages keep the name used at the time.
  - An AI Message stores ordered parts. Each speech part keeps the Character reference and a stamped speaker name.
- The Opening is copied in as the Chat's first Message (model "author") at start and on reset. It can be edited like any other Message.
- An AI Message is stored only when it completes. A failed turn leaves the User Message with a Retry.
- Each AI Message records the status of its two background calls (judge and Memory extraction): pending, done or failed, with a Retry on the dashboard. The next turn's prompt waits until the previous turn's changes are saved.

**Change history and rollback**
- Every AI-made change to Memory, Bond, Arc or Scene is a record. Each record holds what changed, the value before and after, and the causing Message: the AI Message of the turn.
- Rollback undoes records newest first.
- Bond history is kept: the current Bond is its latest change, and the dashboard can expand a Bond to show its history. Scene advances work the same way, at most one per turn.
- User actions on Memory are not tied to a Message:
  - writing, editing or deleting a Memory
  - restoring a Memory from Archived, which locks it
- A user-written Memory is known by the Characters present when it was written.

**Editing** (clarifies [What editing an earlier message does](15-editing-an-earlier-message.md); a comment was added there)
- Discarded Messages and the previous text of an edited Message are deleted for good. There is no version history.
- Editing a User Message makes the AI reply afresh.
- Editing an AI Message rolls back that Message's own changes, re-splits its `@Name:` text into parts and re-runs both background calls. The Chat then waits for the user; the AI does not write another reply.

**Chat, Persona, settings**
- A Chat has a title (default "Chat N", can be renamed), created and last-played times, the worn identity and the current Scene (no current Scene means free play).
- Reset keeps the title and worn identity. It clears every Message, all Memory (user-written included), Bond history, Arc steps and Scene advances. It then re-copies the current Opening and Arc directions, re-seeds the starting Bonds and returns to the first Scene.
- Arc directions are copied into the Chat at start, at reset, and when a new Character joins.
- Personas belong to the app and hold Name + Description only. Snapshots are seen through the user's eyes and never draw the user, so neither Role nor Persona has an appearance field.
- A Persona swap is Chat state. It is never rolled back by an edit. Deleting a worn Persona falls the Chat back to the Role.
- Settings (one per app) hold the play model, the image model and a low-credit threshold for each credit pool.
- A UsageRecord per model call stores its kind, credit pool (text or image), model, tokens or images, cost and the Chat or Story it served. It feeds each pool's monthly spend.

**Story details**
- Voice example lines are an ordered list.
- Secrets and Arc directions are one text block each.
- A starting Bond targets the Role or another Character, at most one per direction.
- Style fields:
  - POV: 1st, 2nd or 3rd
  - tense: past or present
  - reply length: short, medium or long
  - Image style: free text
- Characters and Scenes are ordered.
- Story assistant Undo lasts only while the page is open. Stories keep no version history.
- If a required field is emptied, the Story's Chats stay readable but cannot send until the field is filled again.

**Deleting and changing the cast or Scenes**
- **Delete a Story** (after confirmation): everything goes with it, including its Gallery and reference images.
- **Delete a Chat**: everything goes except its Snapshots, which stay in the Gallery with their links cleared.
- **Remove a Character**:
  - deleted: its Bonds in both directions with their history, starting Bonds pointing at it, its Arc steps, its copied Arc directions and its reference image
  - it is dropped from every Known by; Memories that no one knows anymore stay
  - speech parts and Snapshots keep its stamped name
- **Add Scenes**: a Chat in free play, or one that never had Scenes, enters the first newly added Scene after the last Scene it finished.
- **Reorder Scenes**: each Chat stays on the same Scene.
- **Remove a Scene**: a Chat on that Scene moves to the next Scene, or to free play if it was the last.
- **A failed Snapshot** is not stored. Regenerating a reference image replaces the old one.

Glossary: added **Message**. **Snapshot**, **Gallery** and **Reference image** came from [ticket 06](06-choose-image-model-and-snapshot-behaviour.md).

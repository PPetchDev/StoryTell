# 01 — Import a JSON Character card into a new Story

**Status:** done

**What to build:** The first path through every layer, JSON only. On Home's New Story panel, "From a Character card" opens the file picker; once a `.json` card is picked, the panel shows the file's name, a required "Your name in this Story" field and Import / Cancel. `POST /api/stories/from-card` (multipart `card`, `roleName`, `greeting` default 0) reads a V1, V2 or V3 JSON card and makes a new Story by the spec's fixed mapping (spec: "The mapping"): title, Character name (nickname first), Setting, Opening from `first_mes`, Personality, Background, Example lines split on `<START>`, Lore from `character_book` (disabled, blank and regex-key handling, decorators stripped, constant → Always include), the Role's name, macros replaced everywhere, every text cut at 20,000 characters, Style at its defaults. Creating and filling the Story run inside the import's own cleanup (spec: "Modules"): any failure from creation on deletes the Story and answers the error. AI drafting's create-then-delete is not enough here, since its fill runs outside its cleanup. No model call, no usage record. The card reader, the mapping and the new Character cards error domain (next free domain number) start here with `NoCardFileError`, `UnsupportedCardError`, `CardTooLargeError` (15 MB), `UnreadableCardError` and `InvalidGreetingError`, all in `docs/error-codes.md`. A card carrying Storytell's own `extensions.storytell` block takes the Character's fields, the Role's description and the Style from it. The editor opens on the new Story with the one-time "Made from a Character card" notice and its "Tidy with the Story assistant" button, which opens the assistant sheet with the spec's message filled in and not sent.

**Blocked by:** None — can start immediately.

**Notes (done 2026-11-08):** A JSON array is not read as a card file at all: the spec's kind rule takes only text that opens with `{` as JSON, so a non-object file answers `UnsupportedCardError` (415). `UnreadableCardError` (422) covers JSON that opens with `{` but is broken or not a card, and a PNG's card text that is not an object.

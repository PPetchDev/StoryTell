# 04 — Export a Character as a card PNG

**Status:** ready-for-agent

**What to build:** Every Character's card in the Story editor gets "Export as Character card" at the foot of its body (spec: "Exporting a card", "Web"). The web draws the picture on a canvas (the Reference image at its own size, or, without one, a 512×768 picture of the Character's initial on their Character colour), makes a PNG of it, and posts it to `POST /api/stories/:storyId/characters/:characterId/card` (multipart `image`). The API checks it is a PNG (`NotAPngError` otherwise; `NoImageFileError`, `ImageTooLargeError` at 15 MB), removes any `chara`, `ccv3` and `chara-ext-asset_*` chunks, inserts `chara` (V2) and `ccv3` (V3) built by the card writer from the Character and the Story's Setting, Opening, Lore, Role and Style (the Role's name as `{{user}}`, the labelled description, Example lines as `<START>` blocks, the lorebook, and the `extensions.storytell` block), with CRCs from `zlib.crc32`, and answers it as an attachment named after the Character (ASCII fallback plus RFC 5987 name, as the Transcript does). The web offers the file through the share sheet when the browser can share files, else downloads it. No model call, no usage record. The Story's Documents, the Character's Expressions, and Saved replies and Replace rules are never written (spec: "Exporting a card"); the voices and the Backdrop choice join the block in ticket 06.

**Blocked by:** [02 — Import a PNG Character card with its picture](02-import-a-png-card.md) (the card PNG codec)

- [ ] Pure tests: the V2 and V3 shapes (spec fields, `group_only_greetings: []`, `assets`, dates in Unix seconds, `use_regex: false`); the description's labelled paragraphs with blanks omitted; the Role's name as `{{user}}` only as a whole word; Example lines with and without speaker labels; Lore with blank text left out; chunks replaced, never duplicated; export then import (through the reader and mapping) gives back the same Character fields, Role, Style, Setting, Opening and Lore.
- [ ] API tests: the export answers `image/png` with the file name; its chunks parse to both definitions; a JPEG upload is `NotAPngError`; an unknown Character is `CharacterNotFoundError`; ids, Chats and Memories appear nowhere in the definitions.
- [ ] e2e (desktop download path): Export as Character card on a Character with a Reference image downloads `<name>.png`; posting that file to from-card makes a Story with the same Character; a Character without a Reference image exports too.
